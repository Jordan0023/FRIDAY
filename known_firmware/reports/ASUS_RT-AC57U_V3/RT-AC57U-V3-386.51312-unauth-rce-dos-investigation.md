# ASUS RT-AC57U V3 3.0.0.4.386.51312 Unauthenticated RCE/DoS Investigation

Date: 2026-07-24

## Disposition

- Confirmed unauthenticated RCE: **no**
- Confirmed reliable unauthenticated service DoS: **no**
- Confirmed zero-day: **no**
- Strongest residual lead: MiniUPnPd SOAPAction quote underflow, already public
  as CVE-2026-5720, but not dynamically reproduced as a crash in this ASUS
  build

## Security-fix regression differential

The preceding `3.0.0.4.386.51310` release is the relevant security baseline
because ASUS states that it fixed `cfg_server`, token-authentication, HTTP
response splitting, open redirect, and status-page security issues.

Comparison against `51312` produced:

- `infosvr`: byte-identical;
- `cfg_server`: byte-identical;
- `httpd`: `radiff2` similarity 1.000, distance 370; the only printable-string
  change is `Stuff-Fibre` to `Vocus`;
- `miniupnpd`: `radiff2` similarity 1.000, distance 14; the only string changes
  are its February-to-May build date.

No new CGI route, authentication exception, listener, SOAP action, callback
parser, or command string was introduced by `51312`. This rejects a simple
regression of the security fixes documented for `51310`.

## `infosvr` historical-RCE transfer

The exact `infosvr` handler at `0x00403670` was decompiled. It recognizes the
discovery operations `0x1f`, `0x34`, `0x35`, and `0x36`. The historical ASUS
opcode-51 command path is absent from this dispatcher. The binary also imports
no direct command-execution function.

This rejects direct transfer of the historical unauthenticated ASUS discovery
command-execution technique to this build.

## MiniUPnPd SOAP and GENA validation

The stock daemon identifies itself as `miniupnpd 2.2.0 May 8 2023`. Static
decompilation of `Process_upnphttp` recovered the quote-removal arithmetic
described by CVE-2026-5720: a one-byte quoted SOAPAction can reduce the stored
length by two. That is a real code-level match, but CVE-2026-5720 was publicly
disclosed before this investigation and therefore cannot be a zero-day.

The exact daemon and firmware libraries were run under MIPS user-mode QEMU
inside a container with no network interface. Only iptables bookkeeping and
unsupported multicast socket options were replaced; real socket, bind,
listen, accept, receive, send, HTTP, SOAP, and GENA code remained intact.

The live parser returned a 2734-byte HTTP 200 root description before testing.
It then processed:

- the single-quote CVE-2026-5720 candidate: HTTP 500;
- empty GENA callback: HTTP 412;
- callback without an explicit port: HTTP 200;
- 4096-byte callback path: HTTP 200;
- 16384-byte SOAPAction: HTTP 500.

The process remained alive and a final root-description control again returned
HTTP 200 with 2734 bytes. No fatal signal or persistent listener loss occurred.
Thus the public underflow-shaped code is present, but this exact run does not
establish exploitable disclosure or denial of service in ASUS's build.

Reusable artifacts:

- `scripts/probe_asus_rt_ac57uv3_miniupnpd.py`
- `known_firmware/emulation/ASUS_RT-AC57U_V3/miniupnpd_iptc_shim.c`

## Other relevant known-version leads

The firmware ships dnsmasq 2.84. Version matching alone is insufficient to
claim an unauthenticated default-state vulnerability; DHCPv6-related impact
depends on the generated configuration and enabled IPv6 mode.

The filesystem contains WebDAV/AiCloud UI markers, but this pass did not
establish that a vulnerable AiCloud service is installed, enabled, or exposed
at factory defaults. Recent public AiCloud issues must not be relabeled as new
findings.

## Limitations

The component emulator closely reproduces the exact application parser and
libraries but not the router's physical switch, complete NVRAM state, or boot
firewall. A physical factory-reset RT-AC57U V3 is still required to establish
default listener state and device-level recovery behavior. The current
evidence supports “not confirmed,” not “impossible.”
