# GT-BE98 Pro authentic hardware-input inventory

## Recovered from the signed firmware bundle

The following model-wide inputs are present in the stock package and do not
need to be guessed:

- SoC: Broadcom 6813 A0
- board ID: `GT-BE98PRO`
- package/product ID: `GT-BE98_PRO`
- flash build: NAND, pure UBI/squashfs
- U-Boot boot path: present in the signed nested FIT
- board DTB: `fdt_GT-BE98PRO`
- default wireless NVRAM image:
  `/rom/etc/wlan/nvram/GT-BE98PRO.nvm` (63,684 bytes)
- default kernel wireless settings:
  `/rom/etc/wlan/kernel_nvram.setting`
- configured MAC-address count: 11
- build-time placeholder base MAC: `20:CF:30:00:00:00`

The stock scripts require only these `/proc/nvram` names directly:

- `boardid`
- `wl_nand_manufacturer`
- `BaseMacAddr`
- `set` (write endpoint)

For a U-Boot system, bit `8` of `wl_nand_manufacturer` selects the U-Boot
path. Bit `2` selects manufacturing mode. The signed package is a U-Boot FIT,
so the model-wide normal-boot interpretation is U-Boot set and manufacturing
mode clear. A physical capture is still needed to establish the complete
integer value rather than assuming that no additional bits are set.

## Not recoverable from a firmware update

The following are stored on the individual router or generated by its
Broadcom kernel drivers:

- actual per-device base MAC and derived radio MAC addresses;
- calibrated manufacturing wireless NVRAM/SROM;
- complete bootloader environment;
- exact `wl_nand_manufacturer` value;
- device-specific UBI `defaults`, `data`, and manufacturing-NVRAM contents;
- live WLCSM netlink state;
- kernel-generated `/proc/nvram` and `/proc/environment` behavior.

The packaged `GT-BE98PRO.nvm` is an authentic fallback default, but it is not
proof that a retail unit uses it instead of its calibrated manufacturing
copy.

## Effect on activation testing

These recovered values are sufficient to improve a compatibility emulator,
but not to claim a bit-for-bit physical boot. Redirecting `/proc/nvram`
access to model-wide packaged values would be an explicitly modeled
compatibility layer. Any `wl_server_socket` activation observed only after
that intervention would require confirmation against a physical capture.
