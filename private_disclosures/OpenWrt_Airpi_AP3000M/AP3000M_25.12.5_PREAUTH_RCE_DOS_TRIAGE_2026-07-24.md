## Transfer of the RAX30/EX2800 process

The earlier process was applied as a method, not as a blind transfer of
product-specific assumptions:

1. Verify the exact firmware and architecture.
2. Inventory every ELF and rank remotely reachable parsers.
3. Decompile the complete executable corpus and triage dangerous data flows.
4. Re-run the highest-value parser hypotheses against the genuine target
   binaries under architecture emulation.
5. Require a repeatable crash, persistent service loss, unauthorized write, or
   command-execution effect before calling a finding.

The characteristic NETGEAR paths do not exist here. The root filesystem
contains no `miniupnpd`/UPnP daemon, `mini_httpd`, `webupg`, or `start_telnet`
artifact. The viable AP3000M surfaces are the stock OpenWrt services instead:
uhttpd/LuCI/rpcd, dnsmasq, odhcpd, Dropbear, and wpad.

## Dynamic tests against genuine AArch64 binaries

### uhttpd

The image's `/usr/sbin/uhttpd` was run under qemu-aarch64 and bound only to
`127.0.0.1:28083`. The bounded corpus included:

- negative and conflicting Content-Length
- unsupported Transfer-Encoding
- invalid and oversized chunk lengths
- Transfer-Encoding plus Content-Length
- 8 KiB header name
- 8 KiB request target

Responses were bounded HTTP 400, 413, 501, or 502 results as appropriate.
Health checks succeeded after every case. No crash or persistent service loss
occurred.

### dnsmasq 2.93

The image's `/usr/sbin/dnsmasq` was run under qemu-aarch64 on localhost UDP/TCP
port 25354. The corpus included:

- empty and truncated packets
- compression self-loop and two-node loop
- overlong label
- maximum question count
- truncated and oversized EDNS data
- zero-length, truncated, short, and valid DNS-over-TCP frames

The daemon survived every case and returned a valid control response after
each one.

### cgi-io upload boundary

The image's exact `/usr/libexec/cgi-io` was invoked as `cgi-upload` under
qemu-aarch64. The reproducible harness is
`scripts/probe_airpi_ap3000m_cgi_io.py`.

Cases covered a missing session, forged session, shell-shaped destination,
8,192-byte boundary value, and truncated body. Every request exited normally
with `Upload permission denied`; none wrote a file or executed a command.

## Public-prior-art check

OpenWrt 25.12.5 already includes fixes for the then-known uhttpd request
smuggling issues, cgi-io ACL/path traversal issues, and listed odhcpd issues.
Those fixed classes informed the regression corpus; surviving them is not
presented as a new finding.

References:

- https://openwrt.org/releases/25.12/changelog-25.12.5
- https://openwrt.org/docs/guide-developer/security

No public AirPi AP3000M-specific RCE/DoS advisory was located during this
review. Absence from search results is not proof that no private or unpublished
issue exists.

## Conclusion and remaining high-value work

This pass did **not** find a defensible zero-day. The HTTP parser, DNS parser,
and upload authorization boundary—the best host-emulatable pre-authentication
targets—did not produce an exploitable effect.

The remaining targets require device-faithful network state:

1. wpad management-frame fuzzing through the MediaTek radio/driver boundary.
2. odhcpd DHCPv6/RA state-machine fuzzing on a real IPv6 interface.
3. Full-system testing of ubus/rpcd/LuCI interactions with procd, netifd, and
   overlayfs present.

These should be run on an owned AP3000M or an isolated full-system emulation,
with serial/service liveness monitoring and automatic reset. Until one yields
a repeatable unauthorized effect, the correct result remains negative rather
than a claimed zero-day.
