# GL-X3000 production push ACL validation plan

## Current boundary

Firmware-side root command execution is confirmed. Production service
impersonation, cross-device publication, and external ACL bypass are not.
Testing the vendor endpoint requires written GL.iNet authorization and
dedicated test devices/accounts.

## Preconditions

- Written scope names the push hostname/IP and TCP 1887.
- Two researcher-owned X3000 units are enrolled as Device A and Device B.
- GL.iNet supplies a test tenant or confirms that the two serials may be used.
- A maintenance window, source IP, rate limit, and vendor contact are recorded.
- Both routers have packet capture and console recovery available.
- No `sh_exec`, profile mutation, or customer identifiers are used.

Stop if any precondition is absent.

## Passive phase

Capture only traffic generated by each owned router:

```sh
tcpdump -i any -s 0 -w /tmp/x3000-a.pcap 'tcp port 1887'
```

Trigger an ordinary eSIM synchronization from the local UI, stop the capture,
and transfer it securely. Decode offline:

```sh
python3 scripts/x3000_push_pcap_audit.py /tmp/x3000-a.pcap
```

Record whether login is plaintext TCP, whether IMEI/EID are identifiers or
authorization factors, whether login nonces prevent replay, and whether the
server supplies a device-scoped session or destination identifier.

## Authorized two-device isolation phase

The vendor should provide a staging publisher or approve a production test
mechanism. Send only this inert, unsupported message to Device B:

```json
{"kind":"acl_probe","codec":"<128-bit-random-nonce>","data":"no-op"}
```

Run four cases and retain server responses plus Device B's passive capture:

1. Device A session targeting Device A: expected accepted/delivered.
2. Device A session targeting Device B: expected denied/not delivered.
3. Replayed expired Device A login targeting Device A: expected denied.
4. Random or malformed signature targeting either device: expected denied.

The nonce must be unique per case. One attempt per case is sufficient. Do not
guess device identifiers, enumerate tenants, scan addresses, or increase rate.

## Decision criteria

- **ACL enforced:** only case 1 reaches its intended owned device; cases 2–4
  receive explicit denial or produce no delivery.
- **Cross-device ACL bypass:** case 2 reaches Device B using Device A's
  authenticated context.
- **Authentication bypass:** case 3 or 4 creates an accepted session.
- **Inconclusive:** targeting is unavailable, delivery cannot be observed, or
  gateway rejection cannot be distinguished from timeout.

Only after GL.iNet confirms an isolated staging environment should the already
validated marker command be used end-to-end. It must never be sent through the
production service.

## Evidence package

- Written authorization and exact scope
- Firmware hashes and both owned serial numbers (private appendix)
- UTC timestamps and source IP
- Raw PCAP hashes; decoded, identifier-redacted transcript
- One nonce and result per test case
- Router console logs showing no state-changing operation
- Vendor ticket and disclosure timeline
