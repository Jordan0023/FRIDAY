# NETGEAR EX6110 V1.0.1.84 emulation confirmation

Date: 2026-07-23

## Result

The unauthenticated command-execution chain was reproduced end to end using
the official, distinct NETGEAR EX6110 V1.0.1.84 firmware image.

The test ran in a disposable Docker container with `--network none`. The
extender was placed in its factory-unconfigured state and the original
EX6110 `mini_httpd`, `webproc`, and `webupg` binaries were used unchanged.

Observed result:

```text
service_ready=true
unconfigured_state_present=true
setup_trigger_status=200
upgUnauth_created=true
webshell_status=200
upgUnauth_consumed=true
harmless_command_executed=true
command_output_reflected=true
webshell_component_execution=true
unauthenticated_rce_reproduced=true
```

The setup request used an invalid dummy session cookie and caused `webproc`
to create `/var/upgUnauth`. The follow-on request supplied the established
`key=twmode`, attacker-controlled `cmd`, and terminal `name=shell` fields.
The original `webupg` consumed the one-shot marker, passed the harmless
command to `popen`, and reflected its unique stdout token in the HTTP
response.

## Emulation accommodations

The run reused the EX2800 lab's narrowly scoped compatibility artifacts
because the corresponding EX6110 binaries are byte-identical:

- a patched copy named `logic.emu` that bypasses unavailable hardware-only
  initialization while preserving configuration and IPC behavior;
- an MT7628 MTD-ioctl shim for `logic.emu`;
- the existing message-bus compatibility shim;
- a read-only `/proc/llconfig/model` fixture containing `EX6110`; and
- writable disposable runtime files under `/var`.

No patch or compatibility preload was applied to `webproc`, `webupg`, or
`mini_httpd`. The command proof was harmless and based on reflected stdout.
